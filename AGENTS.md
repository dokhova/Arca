# AGENTS.md — правила работы с репозиторием Arca

Этот файл — обязательные правила для AI-агентов (Codex и др.). Нарушение любого пункта = неверное выполнение задачи.

## О проекте

Arca — tarot/astrology Telegram Mini App. React 18 + Vite 6 + TypeScript + Tailwind v4. Деплой: Vercel, авто-деплой с ветки `main`. Язык интерфейса и контента: русский.

## Структура (не менять без явного запроса)

```
src/
  App.tsx                 — роутинг по состоянию, архитектура слоёв
  index.css               — Tailwind + все дизайн-токены (CSS-переменные)
  telegram.d.ts           — типы Telegram WebApp
  components/             — переиспользуемые компоненты
    AppBackground.tsx     — фиксированный фон (луна, свечение)
    BottomNav.tsx         — нижняя навигация
    Modal.tsx             — центрированный попап
  screens/                — по одному файлу на экран
    HomeScreen.tsx
    CardOfDayScreen.tsx
    CatalogScreen.tsx
    SpreadScreen.tsx
    ProfileScreen.tsx
  data/                   — только данные, без JSX
    cards.ts              — 78 карт + getCardOfDay()
    advice.ts             — советы и ритуалы дня
public/
  cards/                  — WebP-изображения карт, slug-имена латиницей
  moon.webp               — луна для фона главной
```

## Железные правила

### 1. Архитектура слоёв — НЕ ТРОГАТЬ
- `AppBackground`: `position: fixed; inset: 0; zIndex: 0; pointerEvents: none`. Никогда не менять на `zIndex: -1`.
- Весь контент — внутри единственной обёртки в `App.tsx` с `position: relative; zIndex: 1`.
- Запрещено добавлять на обёртки контента: непрозрачный `background`, `opacity`, `transform`, `filter`, `isolation` — они создают stacking context и хоронят фон.

### 2. Цвета — только через токены
Все цвета определены как CSS-переменные в `src/index.css`. Новые цвета добавлять туда же. Захардкоженные hex в компонентах допустимы только для одноразовых оттенков, уже присутствующих в коде.

### 3. Один файл — одна ответственность
- Никогда не создавать дубликаты компонентов. Перед созданием файла проверить, что файла с похожим именем нет нигде в `src/`.
- Удалил разметку — удали и её неиспользуемые импорты.
- Никакого закомментированного мёртвого кода.

### 4. Данные неприкосновенны
Файлы в `src/data/` менять только если задача явно про данные. Поля интерфейса `TarotCard` не переименовывать и не удалять — на них завязаны экраны.

### 5. Строго ограниченный объём изменений
Менять ТОЛЬКО те файлы, которые прямо относятся к задаче. Не «улучшать» соседние экраны, не менять layout каталога (он одноколоночный список — всегда), не переформатировать нетронутые файлы.

### 6. Зависимости
Не устанавливать новые npm-пакеты без явного разрешения в задаче. Иконки — только `lucide-react`. Не трогать `package.json`, `vite.config.ts`, `tsconfig.json` без явного запроса. В репозитории используется npm — не создавать `pnpm-lock.yaml`.

### 7. UI-паттерны проекта (уже приняты, не пересматривать)
- Совет дня и Ритуал дня — центрированные модальные попапы (`Modal.tsx`), не bottom sheet, не отдельные экраны.
- Нижняя навигация видна только на корневых экранах (Главная, Каталог, Профиль). На внутренних экранах — круглая кнопка «Назад» слева сверху.
- Карта дня фиксируется на сутки (детерминированно от даты).
- Выбор расклада (1 или 3 карты) — переключатель у зоны выкладки, не отдельный экран.
- Результат расклада сохраняется в localStorage; сбрасывается кнопкой «Повторить расклад».

### 8. Проверка перед завершением
После изменений выполнить `npm run build` — билд обязан проходить без ошибок TypeScript. В конце ответа перечислить все изменённые/созданные/удалённые файлы.
